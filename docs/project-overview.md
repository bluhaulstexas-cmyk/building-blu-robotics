# Project overview — Tim Hauptrief / Building Blu Robotics

The question is simple: how do we build a useful robot, understand what it is doing, and learn from what goes wrong?

TANK-001 begins with one ground vehicle. The work includes selecting a mechanical basis, measuring actual components, printing fit samples, arranging power and protection, and testing manual control before adding more complex behavior.

## Planned sequence

1. **Local build:** one reliable tank, manual control, telemetry and a simple local mission board.
2. **Cooperation and communications:** a second supported ground asset, shared observations and measured mesh-network experiments.
3. **Remote access:** authenticated access to the command interface over existing connectivity.
4. **Later exploration:** supported drone observations and additional robot types, only after separate platform tests.

This is an intended sequence, not a delivery calendar. The project records do not yet establish completed physical tests, validated autonomy or compatibility with every robot.

## How we will tell the story

Each short video or written update follows: **goal → attempt → measured result or failure → next experiment**. Free build resources will be linked when ready and cleared for release. Video production should support the learning rather than delay it.

Tim Hauptrief leads the project. Learning with Tom is part of its purpose. Actual contributions and assistance will be identified as sessions are documented; there is no invented session history.

## AI's role

AI can help explain manuals, compare ideas and suggest experiments. A suggestion is not a measurement. Physical control and stopping need their own tested implementation. Detailed Binder integration is outside this public build overview.
